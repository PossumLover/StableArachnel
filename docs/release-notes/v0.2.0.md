# JamesGames v0.2.0

The first release of **JamesGames**, a fork of [Arachnel](https://github.com/BadKiko/Arachnel) 0.1.47 focused on stability and on running Windows games under Proton on Linux. Your library, settings and Proton prefixes carry over unchanged: the data directory is still `Arachnel`.

## Stability

- **A frozen UI no longer kills the app.** Upstream's hang watchdog called `_exit(1)` after 25 s of UI stall — always at the ~140 s mark, taking in-flight downloads with it. It now writes a report, keeps running, and logs when the UI recovers. Linux hang reports carry a real main-thread backtrace instead of "not captured on this platform".
- **Installing a plugin no longer freezes the UI** while an unrelated download runs.
- **A crashing game can no longer take Arachnel down.** The error-dialog scan could hit a window that had just vanished, and Xlib's default handler then called `exit()` mid-event-loop, which deadlocked on shutdown.
- **Survives plugins that leak file descriptors** — the open-file limit is raised to the hard limit at startup — and log/report writes no longer fail silently.
- Fixed a UI freeze on the Discover tab, a teardown crash in the catalog page, and the QML engine crash on exit.

## Plugins

- **ABI-mismatched plugins are handled safely** (upstream issue #64). The real cause of the FreeTP crash was a *moved virtual function* (`updateMayBreakDlc`) shifting every later vtable slot by one — not the `CatalogEntry` size reported alongside it. Plugins now declare an interface revision, struct drift is reported by name, and a revision-1 shim lets FreeTP v1.0.28 run again.

## Steam compatibility layers

- **Online Fix works where it silently didn't:** the loader is placed next to the game executable, the game is shown its real AppId while Steam sees Spacewar, and existing fix files are never overwritten.
- **SteamFix fallback:** when Online Fix refuses a game with *"Self-protection failed. Error code: 4"* (a per-game `[Hashes]` entry the generic kit lacks), the game is switched to SteamFix. Cities: Skylines II and Core Keeper both start this way.
- **Steam overlay (shift+tab) for Online Fix games**, as a per-game toggle. It needs `SteamLinuxRuntime_4` (sniper's Python 3.9 can't run current Proton), both overlay builds handed to pressure-vessel, and no native-Wayland Proton.
- A refused download fails instead of installing the refusal, and a different version of a fix add-on is tried.

## Launching

- Games launch with `waitforexitandrun`, so protonfixes actually run.
- Steam-style launch options (`%command%`, `VAR=value`).
- DLC is carried through updates, and content left behind by an update is reported.
- The real Proton version is written to the prefix marker; Paradox's launcher is no longer started.

## For debugging

- Every launch writes `launch-<id>.replay.sh` beside its log: the exact command and environment, re-runnable by hand.
- `JamesGames --launch <gameId>` launches through the running instance.
- `scripts/dev/launch-probe.sh <gameId> --headless` runs a game invisibly in gamescope, collects its logs and stops it; `--winedebug +msgbox` captures dialog text.
- Notes on everything above are in `docs/fork/`.

## Known issues

- **Games with a native Linux build can install broken** — e.g. Core Keeper stuck on its loading screen, on Linux *and* Windows. The steamidra plugin installs the Linux depot over the Windows one. Fixed in steamidra; the fix is submitted upstream and **not yet in the store build**. An affected game needs an uninstall and reinstall once a fixed plugin is in place.
- Over **remote desktop** (e.g. KRdp), games that read relative mouse motion can't move the cursor. RDP only delivers absolute pointer positions; it works at the machine.
