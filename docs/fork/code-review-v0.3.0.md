# Sprout v0.3.0 code review

Reviewed `main` at `93553e4`. Game moves and startup pruning were the first priority: both could report normal operation after losing something the user cannot recover by downloading the game again.

## Resolution

| Findings | Change |
|---|---|
| 1, 3, 10 · Files | Cross-volume moves stage a complete directory beside the destination, verify it, publish it, then clean up the source. An occupied destination is refused; failure to clean up the source is a warning after success. Retained download archives keep their actual paths. Linux layout repair merges directory collisions and atomically replaces newer files. |
| 2, 8 · Library | Offline installs keep their records and settings. Game details can recheck an unavailable folder. Background discovery receives a snapshot of the roots and known games; the UI revalidates candidates before adding them. |
| 4, 13 · Play | Linux dependency setup runs on a worker with its own network and process objects, reports progress, and accepts cancellation. Windows tracks a detached game only after finding its executable; a pending launch has a deadline. |
| 5, 9 · Writes | Direct HTTP downloads stream into `QSaveFile` and publish only after commit. Library, settings, and job saves also use checked atomic replacement, surface failures, and retry. |
| 6, 7, 14 · Plugins | Catalog and job futures guard the loaded plugin. A removal timeout leaves it loaded. Quit asks active owned transfers to stop and preserves their resumable job state. An uncooperative plugin stays mapped until process exit. The host now checks the launch-option size before creating the plugin instance. |
| 11, 12 · Online data | Catalog keys use a versioned BLAKE2b digest. Invalid presence responses leave the last valid roster intact; unchanged polls do not rewrite it. |

Regression cases live in [`reliability_tests.cpp`](../../tests/reliability_tests.cpp), [`plugin_boundary_tests.cpp`](../../tests/plugin_boundary_tests.cpp), and [`network_tests.cpp`](../../tests/network_tests.cpp). The original findings below describe the reviewed revision, not the fixed behavior.

## High priority

- [x] **1. Make game moves preserve the complete install.** [`copyPathRecursive` and `movePathRecursive`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/util/file_utils.cpp#L149) enumerate without `Hidden` or `System`, then remove the source. On Linux this skips `.arachnel` and `.arachnel-steamidra`. I exercised the fallback on Windows with an existing destination, a visible file, and a file with the hidden attribute: the move returned success, the source was gone, and only the visible file arrived. There is a second loss path: if copying succeeds but deleting the source only partially succeeds, [the caller deletes the destination too](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/facade/core_wiring_services.cpp#L389). Stage cross-drive copies in a new directory, preserve hidden entries and symlinks, verify before publishing, and treat source cleanup failure as a separate outcome. Never roll back by deleting a pre-existing destination. Test a hidden marker, an existing destination, and a source that cannot be fully removed.

- [x] **2. Keep library records when a drive is offline.** [Startup calls the pruner unconditionally](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/facade/core_controller.cpp#L252). [One failed existence check](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/library/library_maintenance_service.cpp#L53) removes the game and schedules a save. Starting Sprout without a removable drive or before a network share mounts can erase playtime, launch overrides, and component selections even though the install is intact. Mark the game unavailable and retain its record until explicit removal. Test a restart with a library absent, then reconnect it and check that the *same* record is playable.

- [x] **3. Preserve files when Linux install-layout repair encounters a collision.** [The repair loop](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/util/file_utils.cpp#L403) recursively deletes the incoming directory when the normalized destination already exists, even if the two contain different files. For files, it removes the old destination before renaming the replacement; if the rename fails, it falls through and deletes the replacement too. [Play invokes this repair](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/launch/launch_controller.cpp#L859). Merge directories entry by entry, replace files atomically, and leave both versions for diagnosis when replacement fails. Test two colliding directories with different children.

- [x] **4. Move first-launch runtime setup off the GUI thread.** The [zero-delay Play callback](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/launch/launch_controller.cpp#L859) still runs on the launch controller's thread. It [calls `ensureInstalled` synchronously](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/runtime/proton_facade.cpp#L33), and [each installer can wait ten minutes](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/runtime/runtime_dependency_service_helpers.h#L125). Queuing status messages cannot make the UI repaint during that wait. Use asynchronous `QProcess` completion or a worker with its own network/process objects, then resume launch on the GUI thread. A fake slow installer should leave progress, cancellation, and window input responsive.

- [x] **5. Stream direct HTTP downloads to a checked temporary file.** [`HttpDownloadSession`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/jobs/http_download_session.cpp#L98) first reads the body at `finished`, writes it all at once, ignores the write result, and emits success. A game-sized archive can exhaust memory; a full disk can send a truncated archive on to installation. The [TorBox downloader](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/jobs/torbox_download_session.cpp#L365) already demonstrates bounded reads and checked writes. Apply that pattern to direct HTTP, committing the file only after a successful final write. Add a real transport test for multi-chunk responses and write failure: [the current network suite stubs this class](../../tests/transport_stubs.cpp#L22).

- [x] **6. Do not unload a plugin while catalog work is still using it.** Uninstall [proceeds after 30 seconds even when `busy` is true](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/plugins/plugin_facade.cpp#L193). Catalog watchers were [moved to a separate draining list](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/catalog/catalog_controller.cpp#L1347); the [before-unload wait](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/catalog/catalog_controller.cpp#L1323) only joins the original list. If the target plugin is still serving catalog work, its library can be unloaded before that work returns. On timeout, leave it loaded and report that removal is deferred. Use a single per-plugin record of active calls for install, uninstall, and shutdown. Verify that an outstanding catalog request prevents unload even after the UI timeout expires.

## Next fixes

- [x] **7. Request cooperative stop before waiting for plugin downloads on exit.** [Normal shutdown](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/catalog/catalog_facade_install.cpp#L720) stops the built-in transports, then unloads plugins. The [unload hook](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/facade/core_wiring_services.cpp#L138) waits for [every tracked plugin future](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/plugins/plugin_host_async.cpp#L82) when called with an empty ID. No shutdown step asks active plugin-owned transfers to stop first. The window can disappear while the process waits for an hours-long or paused download. Preserve resumable job state, request stop, and wait asynchronously before unloading. Test Quit with a paused, cooperative plugin transfer.

- [x] **8. Take the startup scan's inputs on the UI thread.** [The background task captures a live `LibraryController*`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/facade/core_controller.cpp#L301). [Discovery reads the library store and iterates the storage model](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/library/library_controller.cpp#L906); [`libraries()` returns a reference](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/library/storage_library_model.h#L36) that adding or removing a drive can invalidate. Pass a value snapshot of roots, IDs, and known paths into the worker. On completion, recheck that the destination library still exists before committing each result.

- [x] **9. Make failed saves visible and retryable.** [`jobs.json`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/jobs/job_store.cpp#L164) and [`settings.json`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/settings/settings_store_persistence.cpp#L246) are truncated before the replacement is written. [`LibraryStore::flush`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/library/library_store.cpp#L255) uses `QSaveFile`, but clears its dirty flag before opening the file and ignores `commit()` failure. A disk error can erase the download queue or silently discard a library change. Use a shared, checked atomic JSON writer; clear dirty state only after commit. Test that a failed save preserves the last readable file and a later retry saves the pending change.

- [x] **10. Keep the recorded download path consistent with what actually moved.** [The move request](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/library/library_controller.cpp#L701) moves the installed game directory. [Finalization rewrites `game.downloadPath`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/library/library_controller.cpp#L749) to the destination library's separate `downloads` tree without moving that tree. Retained archives are then left on the old drive while Sprout points elsewhere. Either move the download artifacts as part of the operation or keep their original path. Check both paths with an install that retains its archive.

- [x] **11. Hash every catalog byte when deciding whether a feed changed.** [The fingerprint's tail loop](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/catalog/catalog_disk_cache.cpp#L67) folds up to 31 bytes into a 64-bit integer by shifting; only the last eight survive. I checked two 25-byte JSON payloads that differed only in title (`One` → `Two`): the production function returned the same key. [Catalog loading skips parsing on a key match](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/catalog/catalog_controller.cpp#L88), so a valid update can remain invisible. Use a well-tested fast hash, version the cache key, and cover equal-length edits at each tail position.

- [x] **12. Validate the friends response before replacing local records.** [Presence refresh](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/social/presence_service.cpp#L134) treats invalid JSON or a missing `friends` array in a successful HTTP response as an empty roster. [The merge then replaces the store](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/social/social_controller.cpp#L334), which [immediately writes it to disk](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/social/social_store.cpp#L283). A temporary relay error page can therefore erase local aliases. Accept an explicit empty array as authoritative, but preserve the last good roster for invalid responses. Also skip the disk write when a poll has changed nothing.

- [x] **13. Distinguish a Windows launch request from a tracked game.** [The detached launcher](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/launch/process_launcher.cpp#L229) can return success with PID 0 when no game is observed within roughly 600 ms. [`markRunning`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/launch/launch_controller.cpp#L225) sets the game ID but stops the polling timer for PID 0; [`gameRunning()`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/launch/launch_controller.h#L40) then stays true without a process to observe. Track a pending launch until a matching executable is found or a deadline expires. Test a slow startup and a process that never starts; neither should leave a permanent “running” entry.

- [x] **14. Check the launch-option layout at the plugin boundary.** [The SDK exports `sizeof(GameLaunchOption)`](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/plugins/plugin_api.h#L83), but [the host's comparison table omits it](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/plugins/plugin_host.cpp#L718). A different element layout can therefore pass the handshake even though the host [iterates a vector of those elements](https://github.com/PossumLover/StableArachnel/blob/93553e4e411f177f286c82d516e0edc4d36db33d/src/core/plugins/plugin_boundary.cpp#L257). Compare this field for plugins exposing the size table, before creating the plugin instance. Add a loader test that verifies a reported mismatch is rejected by name.

## Verification of the original review

On Windows 11 with Qt 6.11.1, the rebuilt `tests/` project passed all three CTest targets (`network_tests`, `plugin_boundary_tests`, `window_resize_tests`). The offscreen QML runner reported **32 passed, 0 failed**. The move and fingerprint observations above came from separate, isolated checks against the production functions. The other findings are from tracing the listed source paths; this review did not run a Linux/Proton game or use a live relay.

## Verification of the fixes

All four Windows CTest targets passed, including the new reliability suite. Its local HTTP server exercises a multi-chunk archive, an interrupted response, a destination that cannot be committed, and malformed friends responses. Other cases exercise cache tail edits, cancellation of a real child process, delayed and missing Windows processes, a paused plugin transfer, an incompatible plugin layout, and retry after a failed library save.

The Linux CI suite also includes cross-filesystem moves with hidden files and symlinks, source-cleanup failure, and merging colliding layout directories. Those cases and a live Proton launch were not run on the Windows review machine.
